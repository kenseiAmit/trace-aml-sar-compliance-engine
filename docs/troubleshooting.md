# TRACE Troubleshooting Guide

This guide provides operational solutions for common setup, runtime, and validation issues encountered in the TRACE environment.

---

## 1. Environment & API Connectivity

### Missing OpenAI API Key
- **Symptom**: `⚠️ WARNING: No OpenAI API key found!`
- **Resolution**: Ensure `.env` exists in the project root and contains `OPENAI_API_KEY=sk-redacted`. Check that `load_dotenv()` points to the correct relative path.

### OpenAI Routing & Base URL
- **Symptom**: `AuthenticationError` or `ConnectionError`.
- **Resolution**: OpenAI student accounts require requests to be routed through their gateway. Verify that the client is instantiated with:
  ```python
  client = openai.OpenAI(
      base_url="https://api.openai.com/v1",
      api_key=os.getenv("OPENAI_API_KEY")
  )
  ```

### Insufficient Budget / Rate Limits
- **Symptom**: `Error code: 400 - Insufficient budget: your assignment part budget is exhausted`
- **Resolution**: All core unit tests in `starter/tests/` use deterministic mock clients to verify architecture, Pydantic schemas, validation logic, and authorization gates without consuming API credits. Pre-computed verified filings and audit logs are retained in `outputs/` for grading inspection.

## 2. Agent Output Validation & Compliance Errors

### Narrative Word Count Exceeded (> 120 words)
- **Symptom**: `AssertionError: Narrative exceeds regulatory limit of 120 words`
- **Resolution**: FinCEN Form 111 summaries require strict conciseness. Inspect `ComplianceOfficerAgent._validate_narrative_compliance` to ensure the narrative generation prompt instructs the model to generate between 30 and 100 words.

### Case-Grounded Amount or Date Mismatch
- **Symptom**: `ValidationError: Narrative amounts or dates do not match case records`
- **Resolution**: The substantive compliance validator cross-examines all dollar amounts and dates in the drafted narrative against `case_data.transactions`. Ensure narratives quote exact transaction amounts (e.g., `$67,569.06`) and transaction dates within the case activity window.

### Missing or Fabricated Regulatory Citations
- **Symptom**: `ValidationError: Regulatory citations invalid or missing statutory basis`
- **Resolution**: Citations must match verified legal provisions:
  - Structuring: `31 CFR 1020.320`, `31 U.S.C. 5324`, `31 CFR 1010.311`
  - Money Laundering: `31 CFR 1020.320`, `18 U.S.C. 1956`, `18 U.S.C. 1957`
  - Sanctions: `31 CFR Part 501`, `50 U.S.C. 1701`
  - Fraud: `18 U.S.C. 1344`, `18 U.S.C. 1343`

## 3. Audit Log & Authorization Gate Verification

### Authorization Event Mismatch
- **Symptom**: `ValueError: Authorization event case_id does not match case`
- **Resolution**: SAR filings require cryptographic and audit linkage to a prior authorization event. Ensure `save_sar_document` receives the `auth_event` generated by `evaluate_authorization_gate` and that its `event_id` begins with `AUTH_`.

### Sequential Timestamp Violations
- **Symptom**: Audit timestamps show overlapping or backward time jumps.
- **Resolution**: Ensure all events are logged sequentially using `ExplainabilityLogger.log_agent_action`. Each event timestamp must record actual execution time and reflect non-overlapping chronological progression.
